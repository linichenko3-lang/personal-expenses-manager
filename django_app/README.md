Expense Tracker API
1. Опис проєкту
Expense Tracker --- вебзастосунок для обліку особистих доходів,
витрат і бюджетів. REST API побудований на Django REST Framework та
надає можливість переглядати, створювати, редагувати й видаляти записи.

Для доступу до особистих транзакцій і бюджетів користувач повинен бути
авторизований. Кожен користувач працює зі своїми транзакціями та
бюджетами. Категорії наразі спільні для всіх користувачів: перегляд
доступний авторизованим користувачам, а керування --- адміністраторам.
2. Реалізовані моделі
- Category --- категорія доходу або витрати. Містить назву та тип
  категорії (income або expense).
- Transaction --- фінансова операція користувача. Містить
  категорію, суму, тип операції, дату та опис. Пов'язана з
  користувачем.
- Budget --- бюджет користувача для певної категорії за конкретний
  місяць і рік. Містить ліміт витрат та пов'язаний з користувачем.

4. Приклади HTTP-запитів
У прикладах використовується curl. Для захищених маршрутів передайте
облікові дані або токен відповідно до налаштованого способу авторизації.
YOUR_AUTH_HEADER --- умовне місце для заголовка авторизації.
GET --- отримати список транзакцій
curl -X GET "http://127.0.0.1:8000/api/transactions/" \
  -H "Accept: application/json" \
  -H "YOUR_AUTH_HEADER"
POST --- створити транзакцію
curl -X POST "http://127.0.0.1:8000/api/transactions/" \
  -H "Content-Type: application/json" \
  -H "YOUR_AUTH_HEADER" \
  -d '{
    "category": 1,
    "amount": "1250.00",
    "transaction_type": "expense",
    "date": "2026-11-23",
    "description": "Покупки"
  }'
category має містити ID наявної категорії відповідного типу.
Користувач для транзакції встановлюється на сервері з поточного
авторизованого запиту.
PATCH --- частково оновити транзакцію
curl -X PATCH "http://127.0.0.1:8000/api/transactions/1/" \
  -H "Content-Type: application/json" \
  -H "YOUR_AUTH_HEADER" \
  -d '{
    "amount": "1350.00",
    "description": "Оновлені покупки"
  }'
DELETE --- видалити транзакцію
curl -X DELETE "http://127.0.0.1:8000/api/transactions/1/" \
  -H "YOUR_AUTH_HEADER"
Успішне видалення зазвичай повертає HTTP 204 No Content.
5. Приклад використання власного endpoint (@action)
У TransactionViewSet реалізовано додаткову дію statistics з
декоратором @action.

Запит:
GET http://127.0.0.1:8000/api/transactions/statistics/
Приклад відповіді:
{
  "total_income": "50000.00",
  "total_expenses": "12000.00",
  "balance": "38000.00"
}
Endpoint обчислює загальну суму доходів, загальну суму витрат і баланс
поточного користувача. Значення у відповіді наведені для прикладу.
6. Приклад фільтрації через query parameters
Для фільтрації транзакцій використовується query-параметр
transaction_type.

Отримати лише доходи:
GET http://127.0.0.1:8000/api/transactions/?transaction_type=income
Отримати лише витрати:
GET http://127.0.0.1:8000/api/transactions/?transaction_type=expense
Якщо параметр не передано, API повертає всі транзакції поточного
користувача. Фільтрація не скасовує обмеження доступу до власних
транзакцій.
Документація API
Інтерактивна документація Swagger доступна за адресою:

http://127.0.0.1:8000/api/docs/

7. Тестування API

Для перевірки REST API реалізовано автоматизовані тести з використанням APITestCase із Django REST Framework.

Тести перевіряють:
GET — отримання списку транзакцій повертає HTTP 200 OK.
POST — успішне створення транзакції повертає HTTP 201 Created.
POST — створення транзакції без обов'язкового поля повертає HTTP 400 Bad Request.
PATCH — часткове оновлення змінює лише передане поле, інші дані залишаються незмінними.
DELETE — видалення транзакції повертає HTTP 204 No Content, а наступний GET-запит до цього запису повертає HTTP 404 Not Found.

Запуск тестів
Для запуску всіх тестів застосунку виконайте команду:
uv run python manage.py test django_expenses
